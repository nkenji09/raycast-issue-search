# Raycast Issue Search

GitHub の issue を Raycast から検索し、選んだものをブラウザで開く Raycast 拡張機能です。

認証には、手元の `gh` コマンドのログインをそのまま使います。
Raycast に GitHub へのアクセスを新しく許可する必要がなく、この拡張機能がトークンを保存することもありません。
組織が外部アプリの許可に管理者の承認を求めていても、`gh` で見えるリポジトリならそのまま検索できます。

## 必要なもの

- macOS と [Raycast](https://www.raycast.com/)
- [GitHub CLI](https://cli.github.com/)（`gh auth login` でログイン済みであること）
- Node.js 22.22.2 以上

## 入れ方

Raycast のストアには出していないので、手元でビルドして登録します。

```sh
git clone https://github.com/nkenji09/raycast-issue-search.git
cd raycast-issue-search
npm install
npm run dev
```

Raycast に「Issue を検索」が現れたら、`npm run dev` は Ctrl+C で止めて構いません。登録はそのまま残ります。

初めて開いたら Enter で「リポジトリを編集する」を開き、検索したいリポジトリを 1 行に 1 つ、`owner/repo` の形で書いて保存してください。あとから変えるときは ⌘ ⇧ R で開けます。
`gh` が Homebrew の標準の場所（`/opt/homebrew/bin` か `/usr/local/bin`）に無い場合は、拡張機能の設定画面で「gh コマンドの場所」を入れてください。

## 更新のしかた

Raycast のストアから入れたものではないので、自動では更新されません。新しいバージョンにするときは、clone したフォルダで次を実行してください。

```sh
git pull
npm install
npm run dev
```

`npm run dev` は、Raycast に「Issue を検索」の新しいバージョンが登録されたら Ctrl+C で止めて構いません。

## 使い方

| 操作 | キー |
|---|---|
| ブラウザで開く | Enter |
| URL をコピー | ⌘ Enter |
| 検索するリポジトリ（とプロジェクト）を選ぶ | 検索欄の右のプルダウン |
| Open / Closed を切り替える | ⌘ ⇧ S |
| 自分が担当のものだけにする | ⌘ ⇧ M |
| 詳細パネルを出す・隠す | ⌘ ⇧ D |
| 検索するリポジトリを登録・削除する | ⌘ ⇧ R |
| 親の issue を開く（一番上の親から順に） | ⌘ ⇧ 1、⌘ ⇧ 2 … |
| Issue Type で絞り込む（複数可） | ⌘ ⇧ T |
| Iteration で絞り込む（今・次・前・未設定・名前で選ぶ） | ⌘ ⇧ I |

検索欄に入れた文字は、2 つの方法で探します。

- **タイトルに含む**：最近更新された issue（最大 300 件）のタイトルを、単語の途中や日本語でも部分一致で絞り込みます（`pari` で `parity` が出ます）。
- **GitHub の検索で一致**：本文やコメントも含めて GitHub の検索にかけ、関連の強い順に並べます。こちらは単語単位で一致します。

検索するリポジトリは 1 つです。プルダウンには、リポジトリごとに「リポジトリだけ」と「リポジトリ ・ 紐づいているプロジェクト」が並びます。プロジェクトの組を選ぶと、Iteration の絞り込みはそのプロジェクトで動きます。Issue Type の選択はリポジトリごとに、Iteration の選択はプロジェクトごとに覚えます。

Iteration は「今のイテレーション」のように今日から見た位置で覚えるので、スプリントが替わっても選び直す必要はありません。Iteration で絞っている間は、そのイテレーションの issue を全件取り、タイトルの部分一致もその全件が対象になります。

`123` のように数字から打ち始めると、先頭に `#` が自動で入ります。`#123` のように `#` で始めると、選んでいるリポジトリからその番号の issue だけを探します。このときは Open / Closed・Issue Type・Iteration・担当者の絞り込みは使いません。

検索欄には `label:bug` のような GitHub の検索条件もそのまま書けます。条件を書いたときは、GitHub の検索の結果だけを出します。

親の issue（sub-issue の親）は、一番上までさかのぼって詳細パネルに並べます。⌘ ⇧ D で右に詳細パネルを出すと、タイトルの全文を読め、親をクリックしてブラウザで開けます。行の番号にマウスを載せても、親が「Epic › Feature」のように出ます。一覧で切れたタイトルは、マウスを載せても全文が出ます。

絞り込みと詳細パネルの表示の状態は、次に開いたときも引き継がれます。

## できないこと

- GitHub Enterprise Server には対応していません（github.com のみ）。
- 対象は issue だけで、PR は出ません。
- タイトルの部分一致は、最近更新された 300 件の中だけが対象です。それより古い issue は、GitHub の検索（単語単位）でだけ見つかります。
- Issue Type は組織のリポジトリにしか無いため、個人のリポジトリだけを設定するとプルダウンは「すべての Issue Type」のみになります。
- 複数のリポジトリをまとめて検索することはできません。
- プロジェクトは、リポジトリに紐づいている（Projects の画面で Link したもの）open なものだけが出ます。
- 画面の文言は日本語のみです。
